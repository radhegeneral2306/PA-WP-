# Audit 28 Oct 2026: what's broken (nothing fixed yet)

Four parallel audits (WhatsApp chat, forms + voice, scheduler/data/health, dashboard + security) with temporary probe tests (deleted afterwards). Baseline: 715 tests pass, live build `summary2`. IDs are for picking fixes later.

**FIXED 28 Oct (builds `s1s2`, `s1s2b`): S1, S2, S4, S9**, verified by an independent probe run (max 44-46 subrequests per reminder run, reads ~46.6k → ~2-4k/day, 40-task burst all delivered once). Follow-ups from that verification also fixed: summary without text fallback (was 59 calls when the template fails), claim-before-send (no 5-minute repeat if the mark fails), store errors counted in health, empty reminder time cleared. See HANDOFF section 8.

**Plans (owner, 28 Oct): Cloudflare Workers FREE (50 subrequests per run) and Firebase SPARK free (50k reads/day).** So S1 = Critical, S2 = High, S4 = Medium.

Fix options to decide with the owner:
- S1 (code, free): send reminders per task (save `nextReminderAt` only after a successful send) and cap each 5-minute run at ~10 reminders; the rest go out in the next runs (still within minutes). Reuse one OAuth token per run (S9).
- S2 (code, free): query only due tasks (`nextReminderAt <= now`, one range filter, automatic index) instead of reading every pending task 288 times a day.
- Or/also upgrade: Cloudflare Workers Paid (~$5/month, 1000 subrequests) and Firebase Blaze (pay as you go; at this volume likely near zero, set a budget alert).
