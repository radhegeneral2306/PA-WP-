# Radhe Tasks dashboard (PWA)

Mobile-first, installable dashboard for the WhatsApp task bot. Static site (Vite + React + TypeScript + Tailwind v4) that talks to the bot Worker's `/api/*` routes. Design rules: `../docs/DASHBOARD-DESIGN.md`. API contract: `../docs/DASHBOARD-API.md`.

Phase 3 status: read-only (login, "Aap kaun ho?", pending tasks with filters and search, task detail, archive, settings, PWA shell). Action buttons are visible but disabled until Phase 4.

## Run locally

```bash
cd dashboard
npm install
npm run dev        # http://localhost:5173
npm test           # unit tests (vitest)
npm run build      # type-check + production build into dist/
npm run preview    # serve dist/ on http://localhost:4173
```

Note: the Worker only allows the dashboard's own origin (CORS), so a local dev server can only log in if that origin is allowed on the Worker.

## Config

| Env var | Default | Notes |
|---|---|---|
| `VITE_API_BASE` | `https://pa-wp-bot.radhegeneral2306.workers.dev` | Worker base URL. Not a secret. Read at build time. |

| Setting | Value |
|---|---|

Pages runs `npm ci`, so `package-lock.json` must stay committed.

## PWA

- Manifest and service worker come from `vite-plugin-pwa` (see `vite.config.ts`).
- The service worker precaches the app shell only. Every `/api/` request and the API origin are NetworkOnly: task data is never cached.
- `registerType: "prompt"`: when a new version is deployed, the app shows "Naya version aaya hai" with a Reload button.
- Icons in `public/` are generated by `npm run icons` (`scripts/make-icons.mjs`, Node built-ins only). Re-run it only if the accent color changes.
